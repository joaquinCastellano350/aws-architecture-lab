# RFC & Project Brief: Cloud Architecture Construct Library

## 1. Context and Vision
The goal of this project is to build a reusable **L3 Custom Construct Library in AWS CDK (TypeScript)** designed to standardize and accelerate the delivery of modern cloud workloads across AWS.

Rather than locking into a single paradigm (such as strictly Serverless or pure Event-Driven Architecture), this library functions as an **enterprise-grade infrastructure design system**. It provides modular, resilient, and preconfigured architectural building blocks that span serverless services, containerized workloads, managed datastores, and networking primitives.

---

## 2. Problems to Solve
* **Paradigm and Runtime Coupling:** Hardcoding serverless-only or container-only assumptions into infrastructure components instead of supporting compute-agnostic patterns.
* **Inconsistent Resilience Defaults:** Repeatedly provisioning messaging, databases, and APIs without production-grade error handling (DLQs, automated retries, connection lifecycle, and monitoring).
* **Network & State Mismanagement:** Construct anti-patterns where VPCs, subnets, or stateful resources (RDS/DynamoDB) are duplicated, tightly coupled to ephemeral stacks, or exposed to accidental deletion.
* **IaC Boilerplate Duplication:** Re-implementing baseline setups for APIs, relational/NoSQL databases, authentication, and secure networking across multiple projects.

---

## 3. Initial Project Scope

### Phase 0: Library Foundations & Tooling
* Project lifecycle orchestration and package management via **Projen** (`awscdk-construct-library`).
* Strict `peerDependencies` enforcement (`aws-cdk-lib`, `constructs`) to eliminate version clashes across downstream stacks.
* Baseline unit testing suite and synthesis assertions using `aws-cdk-lib/assertions`.
* Standardized metadata envelope and distributed tracing contract (`correlationId`, `traceId`, `timestamp`, `version`) agnostic of runtime transport.
* Local sandbox/workspace setup to test constructs against an isolated AWS sandbox without external package registry deployment.

### Phase 1: Modular Foundation Constructs
1. **Network Primitives:** Helper constructs for non-intrusive VPC ingestion, private subnet integration, and security group encapsulation.
2. **Resilient Queues & Event Buses:** SQS constructs preconfigured with Dead-Letter Queues (DLQs) and automated CloudWatch alarms; EventBridge buses configured with logging and schema validation hooks.
3. **Stateful Stores (Relational & NoSQL):** 
   * Managed DynamoDB constructs featuring preconfigured TTL, point-in-time recovery (PITR), and strict removal safety policies.
   * Secure relational constructs (e.g., RDS / Aurora Serverless) with integrated AWS Secrets Manager credential rotation and snapshot deletion policies.
4. **Compute-Agnostic Worker Patterns:** Reusable worker integration patterns adaptable to either **AWS Lambda** (short, event-triggered tasks) or **Amazon ECS on AWS Fargate** (long-running, memory-intensive jobs).

### Phase 2: Pilot Architectural Use Case (Distributed Transaction Orchestrator)
* Implementation of an end-to-end distributed transaction workflow (e.g., Payment & Order Lifecycle) orchestrating:
  * Ingestion via API (HTTP or WebSocket for real-time status).
  * State coordination using **AWS Step Functions** (Saga Pattern) managing reservation, charge capture, and rollback logic.
  * Mixed-compute execution: decoupling serverless event dispatchers from containerized or relational worker tasks.

---

## 4. Architectural Design Principles
* **Compute & Runtime Agnosticism:** Infrastructure contracts should define *capabilities* (e.g., "Event Consumer," "Scheduled Processor") rather than strictly hardcoding the underlying execution engine.
* **Inversion of Control (IoC):** The construct enforces compliance, security boundaries, and resilience; the consumer injects the domain logic, existing VPCs, or specific task definitions via `props`.
* **Safe State Management:** Stateful resources (databases, object storage) must strictly default to `RemovalPolicy.RETAIN` or `RemovalPolicy.SNAPSHOT` with explicit opt-ins required for destruction.
* **Zero Cross-Stack Reference Lock:** Eliminate brittle CloudFormation exports (`Fn::ImportValue`); prioritize parameter lookups, explicit interface injection, and ARN references.
